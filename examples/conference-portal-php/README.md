# Конференции.РФ · PHP + MySQL / XAMPP

Самостоятельный учебный пример для КИМ 09.02.07-3-2027, ГИА базового уровня. PHP 8.2+, PDO MySQL, MariaDB/MySQL, локальные PT Sans и изображения. Python для работы этого варианта не нужен.

## Запуск в XAMPP на Windows

1. Распакуйте архив в `C:\xampp\htdocs\conference-rvpm-2027` (в папке должен быть `index.php`).
2. Запустите Apache и MySQL в XAMPP Control Panel.
3. В http://localhost/phpmyadmin создайте **новую пустую** базу `conference_php_2027` с кодировкой utf8mb4. Не используйте базу Flask: хеши паролей у примеров различаются.
4. В PowerShell выполните:

```powershell
cd C:\xampp\htdocs\conference-rvpm-2027
& C:\xampp\php\php.exe setup.php
```

Инициализация доступна только из командной строки и отказывается изменять непустую базу. Она создаёт структуру, шесть помещений и администратора. Не нужно импортировать схему перед запуском setup.php.

5. Откройте http://localhost/conference-rvpm-2027/.

В стандартном локальном XAMPP используются host 127.0.0.1, port 3306, user root, пустой пароль. Для другой конфигурации задайте MYSQL_HOST, MYSQL_PORT, MYSQL_DATABASE, MYSQL_USER, MYSQL_PASSWORD в окружении запуска **Apache** и CLI. Не храните пароль в репозитории. Базу можно также проверить через встроенный сервер `php -S 127.0.0.1:8087`, запущенный из папки проекта с теми же переменными.

## Что умеет пример

Регистрация, хеширование пароля, вход с сессией, каталог помещений, заявка, личные заявки, панель администратора с поиском и фильтром статуса, смена статусов, отзыв только после завершения. Сервер проверяет CSRF, владельца заявки, роль, обязательные поля и значения справочников. SQL выполняется через подготовленные запросы PDO. Вход и регистрация имеют общий ограничитель попыток по IP.

Учебный администратор из КИМ: **Conf2027 / Demo77**. Пользователи регистрируются с паролем от 8 символов.

## ER и происхождение данных

- users: логин, пароль, ФИО, телефон, e-mail — форма регистрации, КИМ стр. 34. password_hash — способ безопасного хранения пароля, is_admin — серверная роль.
- rooms: список помещений — КИМ стр. 33 и 36. Шесть демонстрационных площадок в rooms.json — данные примера, не официальный список из КИМ.
- applications: user_id берётся из сессии, room_id — из выпадающего списка. Дата, время, оплата — из формы заявки; новый статус задаёт сервер. КИМ стр. 33–35.
- reviews: application_id — выбранная своя заявка, user_id — сессия. Сервер проверяет завершение; UNIQUE(application_id) запрещает второй отзыв. КИМ стр. 36.
- rate_limits — техническая защита, не отдельное требование КИМ.

Связи: users 1:N applications; rooms 1:N applications; applications 1:0..1 reviews; users 1:N reviews. Создайте ER-схему в своей СУБД и сохраните её в папку проекта. В учебном сайте есть пошаговый разбор полей и связей.

## Структура

`index.php` — маршруты и формы, `lib.php` — класс Database и функции, `schema.sql` — структура и FK, `setup.php` — безопасная первичная инициализация пустой базы, `rooms.json` — демонстрационные помещения, `static` — локальный дизайн и микроанимации.

## Ограничения

Нет настоящей оплаты, отправки писем и проверки пересечений времени бронирования. Это учебные заявки, не реальное резервирование площадок. Перед публичным размещением смените учебные реквизиты, настройте HTTPS и отдельного пользователя БД. Каталог и контакты демонстрационные. Сохраняйте в Git код, ER, схему и README, исключайте пароли, сессии и личные данные.
